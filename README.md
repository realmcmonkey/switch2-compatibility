# Switch 2 Compatibility Library

A community-maintained compatibility library. The React frontend is deployed to GitHub Pages; an Express API runs on Vercel and connects to TiDB Cloud. Games and emulators publish immediately; reports require administrator approval. No games, ROMs, or video files are hosted.

## Required setup

1. **TiDB Cloud:** Create a database in your `switch2-compatibility` cluster and execute `schema.sql` with a SQL client. Create an application database user with only the privileges needed for this schema. Obtain the TLS connection string and ensure Vercel can reach the cluster under its network access rules. TiDB requires TLS; `DATABASE_SSL=true` is the default. The server validates the certificate using the runtime's trusted CAs.
2. **Discord Developer Portal:** In your application, add `https://YOUR-VERCEL-DOMAIN/api/auth/callback` as an OAuth2 redirect URI. Copy the client ID and client secret. The application requests only the `identify` scope. Enable Discord developer mode to copy your numeric Discord user ID for administrator configuration.
3. **Vercel:** Import this repository as a project. Set `DATABASE_URL`, `DATABASE_SSL`, `SESSION_SECRET` (at least 32 random characters), `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`, `DISCORD_REDIRECT_URI`, `ADMIN_DISCORD_ID`, `FRONTEND_URL`, and `NODE_ENV=production` in Vercel's server environment. `FRONTEND_URL` must be `https://realmcmonkey.github.io/switch2-compatibility/` including its trailing slash. `DISCORD_REDIRECT_URI` must exactly match the URI in Discord. `DATABASE_URL` is a MySQL URL, for example `mysql://USER:PASSWORD@HOST:4000/DATABASE`; URL-encode special characters in credentials. Deploy after setting these variables. Never put secrets in GitHub or variables prefixed with `VITE_`.
4. **GitHub Pages:** In repository Settings → Pages, select GitHub Actions as the source. Add a repository Actions variable named `VITE_API_URL` with the Vercel origin, for example `https://YOUR-VERCEL-DOMAIN` (no `/api`). Push to `main` or `master` or run the workflow manually. The build publishes `dist`. Routes use hash navigation, so direct links such as `https://realmcmonkey.github.io/switch2-compatibility/#/games/1` work on GitHub Pages without server rewrites. If the repository name changes, set `VITE_BASE_PATH` at build time.
5. Sign in with Discord once using the configured administrator ID. Visit `#/admin`. Catalog entries can be added after sign-in; compatibility reports are held for moderation. Configure the real Discord community invitation separately if you want a public community link; no invite was provided.

## Local development

Use Node 22 or newer. Run `npm ci`, copy `.env.example` to `.env`, and set your own development credentials. Start the API with `npm run server` and the frontend with `npm run dev`. For local OAuth, register a local callback with Discord, set `DISCORD_REDIRECT_URI=http://localhost:3000/api/auth/callback`, and set `FRONTEND_URL=http://localhost:5173/`. Set `DATABASE_SSL=false` only for a local database that does not support TLS. `npm test` runs permission and validation tests; `npm run build` builds the frontend. Never commit `.env`.

## Design and operation

The API uses parameterized queries, database uniqueness constraints, per-instance request limits, origin checks for state-changing requests, signed HTTP-only sessions, server-side Discord-ID authorization, pagination, and indexes for report queries. The database pool is limited per serverless instance; monitor TiDB connections under load. For production at scale, configure a shared rate-limit store or edge/WAF limits: the included in-memory limits are per Vercel instance and do not constitute a global quota. Use monitoring and backups appropriate to your TiDB plan. Search uses a name `LIKE` query and is paginated; for very large catalogs, introduce a search index or prefix search after measuring actual workload. Reports are fetched 20 at a time and indexed by game/emulator and moderation status.

The browser must allow cross-site cookies for the GitHub Pages and Vercel origins. Some browsers block third-party cookies, which can prevent sign-in; a custom domain with frontend and API under the same site is recommended for reliable authentication. OAuth state and session cookies are `Secure`, `HttpOnly`, and `SameSite=None` in production. Sessions last seven days. No Discord email or access token is stored.

Wikipedia lookups use exact page titles or an explicitly supplied English Wikipedia article, and avoid disambiguation pages. Wikipedia text and media may carry attribution, share-alike, or non-free restrictions. Review each result, verify that it is the intended subject, and record the correct author, source, and license before publication; an absent match is left blank. Images are remote URLs, one per entry, rather than uploaded files. External images reveal visitor IP addresses to their hosts. Trailers are YouTube URLs embedded with the privacy-enhanced domain. URLs and descriptions can be corrected by their submitter or an administrator.

Administrator actions are recorded in `moderation_log`. Suspended or banned accounts cannot submit or edit. Entry names are normalized for exact duplicate detection, but administrators should still review similar names manually. Entry deletion is blocked while reports reference it; remove associated reports first. There is no automatic merge of duplicate entries.
